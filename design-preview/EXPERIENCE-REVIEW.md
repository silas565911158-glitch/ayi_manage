# 上户考勤 v1.1 全闭环体验审查

## 审查对象

- 视觉与交互原型：`design-preview/index.html`
- 原型真实应用视口：`375 × 812`
- 角色旅程：雇主创建合作 → 阿姨核对匹配 → 双方当期记工 → 雇主补录 → 雇主结算 → 阿姨确认 → 历史归档 → 终止 → 重新合作

## 已在原型中补齐的闭环

1. **身份选择**：仅保留雇主 / 阿姨两个大按钮。
2. **创建合作**：价格、日薪、开始日期、地址、围栏半径。
3. **等待匹配**：8 位匹配码、有效期、合作信息、复制 / 重生成 / 返回修改 / 重新选择身份。
4. **阿姨核对匹配**：先核对价格、日期、地址、围栏，再确认。
5. **阿姨当期**：本期天数、累计工作、今日状态、日历事实、打卡按钮。
6. **雇主当期**：本期天数、累计支付、日历事实、结算 / 补录 / 终止。
7. **补录**：连续日期批量选择、单日修改、默认 09:00、默认「前期补录」、已打卡日期不可修改。
8. **雇主结算**：合同口径、本期计算、实付金额、差额原因、转账截图。
9. **阿姨确认结算**：口径、实付、凭证、确认后新期开始日。
10. **新一期状态**：确认后回到当期，新期从上一期截止日后一天开始；若结算确认当天即新期开始日，当天可继续打卡。
11. **历史档案**：合作切换、三项汇总、合同信息默认收起、结算 list。
12. **终止合同**：后果说明、当前状态、终止原因、强确认。
13. **合作结束**：历史归档提示、雇主与阿姨各自的下一步。
14. **状态兜底**：成功、失败、权限、锁定、空态、弱网。

## 原型中统一的核心样例

为了闭环口径一致，原型使用同一条事实链：

```text
合同开始：2026.08.12
第 1 期：2026.08.12 至 2026.09.08，干了 26 天，支付 ¥8,000
第 2 期：2026.09.11 至 2026.10.08，干了 26 天，支付 ¥8,000
第 3 期：2026.11.01 开始
已打卡 10 天，其中 1 天为补录
雇主补录 11.09、11.10 后：本期 12 天，其中补录 3 天
第 3 期截至 2026.11.12
2026.11.13 发起结算：8000 ÷ 26 × 12 = ¥3,692.31
阿姨确认后：历史 3 期，累计 64 天，累计支付 ¥19,692.31
第 4 期：2026.11.13 开始
```

结算周期规则：

```text
只要有已打卡天数就可以发起结算
结算截止日 = 当前期最后一个已打卡日期
新期开始日 = 结算截止日的下一天
若结算确认当天等于新期开始日，当天可以继续打卡
```

补录规则：

```text
可补范围 = max(本期开始日, 今天往前30天且不含今天)
只能补当前未结算期
只能补未成功打卡日期
默认时间 09:00
默认原因：前期补录
```

## 发现的薄弱点与原型修复

### 1. 结算后容易迷路

问题：如果确认结算后直接进历史，用户不清楚新期从哪天开始，也不知道何时能继续打卡。

修复：新增「新一期」状态页。确认后回到当期，显示：

```text
第 4 期 · 2026.11.13 开始
上一期已结算，本期今天开始
本期 0 天
去打卡
```

### 2. 补录容易误改事实

问题：初版补录视觉稿允许跨已结算期，且包含今天，违反事实不可改原则。

修复：

- 只显示当前期可选日期；
- 今天置灰；
- 已打卡日期置灰；
- 连续选择只选择可选日期；
- 补录日不额外标注，避免日历拥挤；
- 底部只展示补录天数，不展示金额。

### 3. 历史信息抢占主任务

问题：合同信息全部展开会让历史列表被挤压。

修复：

- Header 默认只显示合作切换 + 已结算期数 + 累计支付 + 累计干了；
- 合同信息默认收起；
- 主体是结算 list；
- 每条记录展示期数、起止日期、干了几天、结算工资、平均到岗。

### 4. 日历语义不够自解释

问题：绿点、米黄色、红圈的含义需要用户猜测。

修复：

- 不展示日历图例，保持日历清爽；
- 绿点仅表示当前未结算期已上工；
- 补录日不显示“补”；
- 已结算日期使用黄色圆圈和黄色打卡时间；
- 今天使用红圈。

### 5. 老年用户可读性不足

修复：

- 最小字号 12px / 24rpx；
- 可点击控件最小 44px / 88rpx；
- 主按钮 48px 以上；
- 顶部绿色卡片说明文字改为纯白；
- 字重收敛为 400 / 600 / 700。

### 6. 金额展示风险

修复：

- 金额数字独立样式；
- 已用 `¥100,000` 做 375px 宽度压力测试；
- 无折行、无溢出、无静默截断；
- 闭环样例仍显示真实累计金额，避免数据口径混乱。

## 仍需在小程序和后端实现的 P0

这些能力已经在视觉稿中形成方案，但尚未进入正式业务代码：

1. 结算确认后，新期从上一期最后一个已打卡日期的下一天开始；若结算确认当天等于新期开始日，当天可继续打卡。
2. 日历增加打卡时间；当前期用绿圈，已结算日期用黄圈和黄色时间，不展示图例。
3. 雇主补录接口与页面：
   - 仅当前期；
   - 最近 30 天且不含今天；
   - 仅未打卡日期；
   - 批量提交；
   - 默认 09:00 / 前期补录；
   - 保留操作者、实际操作时间、生效日期和原因。
4. 合同生命周期：
   - `active / ended / cancelled`;
   - 终止原因、终止时间、终止人；
   - 双方 `activeContractId` 清空；
   - 旧历史保留；
   - 双方可重新合作。
5. 历史按合同归档并支持切换。
6. 平均到岗时间：
   - 建议只统计真实定位打卡；
   - 不包含雇主补录；
   - 页面明确标注口径。
7. 去掉客户端可见的内部 openid。

## UI 交付标准

| 类别 | 标准 |
|---|---|
| 应用视口 | 375 × 812，外壳不参与字号评估 |
| 字号 | 12 / 13 / 15 / 17 / 20 / 24 / 30 / 34px |
| 字重 | 400 / 600 / 700 |
| 可点击高度 | 至少 44px / 88rpx |
| 主按钮 | 48px / 96rpx 以上 |
| 圆角 | 8 / 12 / 16 / 999px |
| 金额 | 等宽数字，完整展示，不允许截断 |
| 色彩 | 绿色 = 到岗 / 成功；红色 = 金额 / 支付 / 高风险；墨色 = 当前导航 |

## 验收场景

### 雇主

1. 创建 8000 / 26 合作并看到日薪 ¥307.69。
2. 复制 8 位匹配码。
3. 阿姨加入后看到匹配成功。
4. 查看每天几点上工。
5. 补录最近 30 天内漏记日期。
6. 发起结算并上传截图。
7. 阿姨确认后看到新期开始日。
8. 查看历史档案和每期支付。
9. 本期 0 天时终止合作。
10. 创建新合作且旧历史不丢。

### 阿姨

1. 输入匹配码前核对价格、地址和开始日期。
2. 每天只点一个打卡按钮。
3. 打卡成功看到笑脸和时间。
4. 打卡失败时知道下一步。
5. 日历能看出每天几点上工。
6. 能识别哪天是雇主补录。
7. 能看懂结算口径和实付金额。
8. 确认前知道不能继续打卡。
9. 确认后知道新期从哪天开始。
10. 合作结束后仍能查看历史。
