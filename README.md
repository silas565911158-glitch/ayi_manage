# 上户阿姨记工小程序

原生微信小程序 + 微信云开发实现。默认运行在本地 Mock 模式，可在微信开发者工具中完整体验。

## 业务规则

- 建立合作时输入合同总金额和约定天数，系统自动计算日薪；默认 `8000 元 / 26 天`，即日薪 `307.69 元`。
- 干一天、记一天；不按自然月结算，不自动处理法定节假日。
- 日历只展示当前未结算阶段的成功打卡日期。
- 打卡一天最多成功一次；日期由服务端按 `Asia/Shanghai` 自然日计算。
- 打卡需在家庭围栏内，定位精度不大于 500 米。
- 26 天只是提醒线，不强制结算，也不封顶；超过后继续累计。

## 结算规则

1. 结算入口当前暂隐藏；后续开放后，雇主填写实际支付金额和差额原因。
2. 转账截图必填，最多 3 张。
3. 雇主点击「发给阿姨确认」后，只生成待确认申请，不立即入历史。
4. 待确认期间阿姨不能打卡。
5. 阿姨点击「确认已收到钱」后，生成正式历史记录、关闭旧阶段，并立即恢复打卡；确认后的下一次打卡属于新阶段。
6. 结算发起日不计入旧阶段；上一阶段截止到结算日前一天。
7. 如果结算发起当天阿姨已打卡，则当天不能发起结算，需明天再发起。
8. 阿姨可点击「金额不对，联系雇主」；此时仍不能打卡，需雇主取消后重新发起。
9. 雇主可在阿姨确认前取消；取消后旧阶段继续记工，不生成历史记录。
10. 实付金额可与按合同计算金额不同，但必须填写差额原因。

## 页面结构

首次启动先进入「当期」做状态判断：新用户进入极简身份选择页；已确定角色的用户直接进入对应流程，不再重复选择身份。

小程序使用自定义底部 Tab：

- **当期**：本期已上工、第几期、开始日期、今日打卡状态、当期日历。
- **历史**：已结算期数、累计支付/到账金额、每期工作日期、实付金额和转账截图。

其他页面：

- 身份选择；
- 雇主创建合作并生成 8 位匹配码；
- 雇主等待匹配页；
- 阿姨核对合作信息并输入匹配码；
- 雇主结算确认页。

当前产品优先完成「当期」体验；结算入口暂时隐藏，历史页仅保留基础查看能力。

## 界面约束

- 首次身份选择页只保留两个大按钮，不放说明、广告或调试信息。
- 雇主创建页与阿姨匹配页共用同一套 `flow-*` 页面结构、卡片、按钮和字号。
- 正文字号不低于 `26rpx`，主按钮不低于 `31rpx`，底部 Tab 为 `34rpx`。
- 当期页一屏展示：上方约 1/3 为信息区，其余空间给日历，不出现页面级滚动。
- 阿姨未打卡时显示打卡按钮；已打卡时显示绿色笑脸和打卡时间，不再出现行动按钮。
- 雇主当期信息突出本期进展和累计支付，不展示结算按钮。
- 辅助入口（合作信息、本地体验、重置）统一收进右上角 `⋯` 菜单。
- 底部 Tab 固定贴到屏幕下沿，文字在 112rpx 控件内水平垂直居中，中间有分割线。

## 匹配流程

1. 雇主填写总金额、约定天数、开始日期，并通过地图选择家庭位置和围栏半径。
2. 系统生成 8 位匹配码，24 小时内有效。
3. 雇主把匹配码发给阿姨。
4. 阿姨选择「我是阿姨」，输入匹配码后先核对价格、开始日期、地址和围栏。
5. 阿姨确认匹配后，雇主等待页显示「匹配成功」，双方可进入当期页；匹配码立即失效。
6. 匹配码过期且阿姨未加入时，雇主可在等待页重新生成。
7. 阿姨未加入前，雇主可从等待页返回修改合作信息。
8. 每次修改合作信息都会重新生成匹配码，阿姨已预览的旧匹配码立即失效，必须重新核对后再确认。
9. 雇主等待页和阿姨核对页都可选择「重新选择身份」；未匹配合作会被安全取消，然后重新进入身份选择。
10. 未创建合作前，用户可以回到身份选择页更正身份；双方匹配后不能更换身份。
11. 匹配、修改、重新生成和取消未匹配合作都会在写入时重新校验合同未绑定，避免并发下误绑定或误取消。

## 本地开发

```bash
npm install
npm run verify
```

用微信开发者工具导入项目根目录：

- AppID：正式小程序 `wx56fd09f940f30024`。
- 小程序代码：`miniprogram/`。
- 云函数：`cloudfunctions/attendance/`。
- 默认运行模式：云开发。
- 云环境：`aunt-attendance-prod-d3aa5daba41`。

Mock 模式使用 `mock-employer` 和 `mock-employee` 模拟两个用户。当期页右上角 `⋯` 菜单可切换体验身份或重置本地数据。

## 切换云开发

1. 注册正式小程序并替换 `project.config.json` 的 `appid`。
2. 开通云开发，得到环境 ID。
3. 修改 `miniprogram/config/runtime.js`：

```js
module.exports = {
  mode: 'cloud',
  cloudEnv: '你的云环境ID'
};
```

4. 上传部署 `cloudfunctions/attendance`，选择云端安装依赖。
5. 创建集合：`users`、`contracts`、`cycles`、`checkins`、`checkin_attempts`、`challenges`、`settlement_requests`、`settlements`。
6. 建议索引：
   - `contracts.inviteCode`
   - `contracts.employerOpenid`
   - `contracts.employeeOpenid`
   - `cycles.contractId`
   - `checkins.cycleId`
   - `checkins.contractId + localDate`（唯一）
   - `settlement_requests.contractId + status`
   - `settlements.contractId + settledAt`
7. 客户端不直接读写业务集合；集合权限可设为仅云函数/管理员读写。
8. 转账截图会上传到云存储：

```text
transfer-proofs/{contractId}/{timestamp}-{index}.jpg
```

共享业务代码位于 `shared/`。修改后执行：

```bash
npm run sync:shared
npm test
```

测试会检查云函数与小程序内共享代码副本没有分叉。

## 手工验收

1. 新用户进入身份选择页，页面只有「我是雇主」「我是阿姨」两个按钮。
2. 雇主创建 `8000 / 26` 合作，进入等待匹配页，页面实时显示 `每天 ¥307.69` 和匹配码。
3. 复制匹配码，切换阿姨身份；阿姨先核对合作信息，再确认匹配。
4. 雇主等待页显示「匹配成功」，双方进入当期页。
5. 关闭后重新打开，双方直接进入当期页，不再进入身份选择页。
6. 阿姨在「当期」页看到本期天数和日历。
7. 模拟家庭位置打卡成功，日历出现标记。
8. 同一天第二次打卡被拒绝。
9. 匹配码过期前，雇主可在等待页返回修改或重新生成。

## 发布检查

1. 执行 `npm run verify`，确认共享代码同步且全部测试通过。
2. 微信开发者工具执行普通编译，确认无 WXML / WXSS / JSON 错误。
3. 真机分别体验雇主、阿姨和重新选择身份流程。
4. 替换正式 AppID，并在微信公众平台完成位置等隐私接口声明。
5. 切换云开发模式、部署云函数、创建集合和索引。
6. 真机验证授权、打卡、日历和同日重复打卡限制。
